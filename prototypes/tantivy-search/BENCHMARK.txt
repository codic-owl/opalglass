Validation:
- Five release tests passed: searchable unstored bodies; exact/fuzzy ranking; transpositions and two-edit title correction; exact quoted phrases; ordinary AND semantics; prefix limits; Unicode highlights; late matches in a 1.6 MB file; common-word position lists; skipped long tokens; cached reads; changed/deleted files; cancellation; outside-vault symlinks.
- cargo clippy --all-targets -- -D warnings, cargo fmt --check and git diff --check passed.

Method and limits:
- Rust 1.90, Tantivy 0.26.2, portable release CPU target. One new index build. An initial query run exposed a relevance/latency problem; the final query run reused that same index after fixing it. Initial metrics are retained as bench-v2-initial.json.
- Title-derived corrections are reused for body retrieval. Known words in multiword queries remain exact. Broad body expansion is limited to one edit; two-edit corrections require a title match. Expansion caps can reduce recall and are reported.
- Search timings exclude snippets and UI. Snippet timings include source metadata checks, bounded reads, passage selection and JSON construction. Cached measurements still check metadata.
- Queries run once then twenty times for warm median and nearest-rank p95. Uncached snippet samples clear the snippet cache, not the OS filesystem cache. First-call measurements are recorded in JSON; this is not a cold-disk test.
- The side-by-side snippet test uses identical phrase-query hits for both paths, with one sample each. Different passage selection and excerpt lengths (~200 old / ~240 new) mean excerpt content need not be identical.
- Unquoted v2 queries use token AND, not the v1 phrase default or the app arbitrary-substring scan. For example unquoted divine light now returns 1,115 exact-token AND hits; quoted phrase comparison uses the original 105 matches.
- The 16 KiB source-read cap does not bound term-position decoding; a very frequent term still requires decoding its position list. Passage candidate sampling and rare pathological limits are documented in README.txt.
- Memory is the standalone process and pages touched by these queries, not eventual GUI RAM. Fuzzy queries visit more index pages than v1 exact-only tests. Build timings vary with system/cache state; this is not evidence that adding checkpoints inherently speeds indexing.
- No watcher, incremental updates, dirty-buffer overlay or app integration. Changed files yield stale snippets until rebuild; same-size edits preserving mtime are not detected.
